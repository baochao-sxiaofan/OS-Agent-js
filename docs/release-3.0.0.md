# OS-Agent-js 3.0.0

发布日期：2026-10-23。根包和 OS Agent Next 桌面版本统一为3.0.0。

本次改版从一次任务对应一棵 Agent 树，转向用户创建、长期保留的独立 Agent。
工作完成后 Agent 休眠，新的用户消息或协作消息唤醒原身份，继续使用持久记忆与权限。
新桌面围绕联系人、私聊和群聊工作；服务器使用相同 Runtime。

## 模块职责

| 模块 | 负责 | 边界 |
| --- | --- | --- |
| agent-control-block | 长期身份、权限元数据与四态转换 | 不规划业务、不调用模型 |
| agent-scheduler | 请求调度、在途操作、结果批次、等待与唤醒 | 不理解 L1/L2/L3 业务语义 |
| agent-context | 三层任务链、来源、记忆、压缩与持久化 | 不访问 UI，不执行业务工具 |
| agent-round | 普通轮、独立总结、Context 提交 | 通过接口连接调度与模型 |
| model-requester | 厂商消息协议、原生工具、私有续接、网络错误 | 不调度、不执行工具、不管理权限 |
| agent-runtime | 编排上下文、模型、工具、权限、会话和恢复 | 向宿主提供公共 API |
| integrations | MCP 与 Docker 后端 | 宿主显式注册后才开放能力 |
| desktop-next / server | UI、IPC、HTTP、配置与宿主生命周期 | 核心不反向依赖 Electron 或 React |

L1/L2/L3 是同一 Agent 的内部上下文，不代表三个 Agent。协作消息只传资料，
不能创建身份、取消协作者或转授权限。工具可见性与实际授权分别校验。

## 桌面与会话

- 新建 Agent 后等待消息；完成工作保留身份、上下文和历史。
- 独立用户私聊、Agent 私聊和群聊；当前批次固定处理上界，在途新消息留给后续批次。
- 只有 `message_send` 产生聊天气泡，内部完成与总结保持内部记录。
- “我的对话”显示用户参加的会话；“Agent 视角”只读查看，不清未读、不加入会话、不触发回复。
- 群聊支持点名与自主参与；宿主控制自动发言预算，避免互相回复无限循环。
- 历史字面检索、原文分页、会话摘要与长备注；用户和 Agent 各自维护备注，版本检查防止覆盖。
- DeepSeek / MiniMax 独立凭据和型号，模型发现与推理分离，Key 只在主进程使用。
- 500K/1M 请求容量预设、自定义输出与分层压缩阈值；达到工作额度后保留现场。

## 运行可靠性

新链路普通动作、分层总结和会话摘要统一使用原生工具调用。工具调用 ID、真实回执
和私有思考续接按 Agent、会话、工作批次与上下文范围保存；不将私有状态放进聊天或语义记忆。
来源按当前活动步骤校验，原文封存可分页读取，不用压缩删除原始证据。

修复 DeepSeek `context_step_completed` 嵌套 Schema 根相对引用错位引起的HTTP400，
升级时重建未完成旧请求，已完成回复按幂等回执恢复。HTTP错误、协议错误、超时、
限流、审批与未知副作用有明确的重试或暂停路径。

默认128次请求额度按工作批次计算；新来信取得新额度，自动重试和重启不会重置。
用户继续可追加额度，累计请求、Tokens和费用不清零。未知写入不能自动当作失败重做，
须经可信宿主对账。

## 兼容与安装

旧 `desktop/` 保留2.2.1和原应用标识，新 `desktop-next/` 使用 OS Agent Next、
`com.osagent.desktop.next` 及独立数据目录。旧 TCB/Graph 身份不自动迁移为长期 Agent，
旧数据库保留。已有兼容的新桌面联系人、会话与模型配置继续恢复。

macOS 从 `npm run desktop:next:pack` 生成 `.app`，关闭原实例后替换应用程序中的包。
用户数据存于 `~/Library/Application Support/OS Agent Next`，不随安装包覆盖。
本地包未签名或公证。

Windows CI 分别打包两套桌面；新安装器为 `OS-Agent-Next-Setup-3.0.0-x64.exe`，
旧安装器仍为2.2.1。根包保留旧导出，新链路通过独立子入口提供，不自动接管旧执行状态。
依赖锁文件使用 npm 官方下载来源，运行示例不包含本机私人工作区默认路径。

## 真实协作证据

DeepSeek `deepseek-flash` 的两 Agent 测试从空数据库只派发一条用户任务，
723秒内完成176次模型请求、37条 Agent 消息及十章正文与清单交付，共21169汉字。
十章均由作者工具实际写入，双方读取最终内容的SHA256与磁盘一致，
编辑确认晚于最终读取；最后双方休眠、队列为空。88次文件及目录操作全部成功。

176次接口响应全部HTTP200。一次不允许的函数返回未执行，自动纠正成功；
14次本地主动准入等待自行恢复。没有人工继续、宿主补发、代写或伪造回执。
本测试不评价剧情、人物或文风。

额外的“每章交稿后独立补写、编辑再复读”流程覆盖8/10。
第08、10章提前将补写放进初稿，编辑实读后直接确认；严格流程脚本继续保留未通过标记。
十章交付成功不能替代这个额外用例的全覆盖证据。

## 当前范围

本次交付为单进程 Runtime 与本机桌面，不提供分布式调度、远端桌面同步、
流式聊天、附件或向量语义搜索。Docker 隔离与目标 Linux/systemd 实机验收仍需对应环境。
未验证的部署平台不会用本机测试结果代替。

## 发布前审查与修复

本次按六组审查全部改版源码及新文件，并做跨组接口复核。确认的功能问题已修复：

- 旧休眠调度快照保留宿主已有新工作的 READY 意图；同组重复操作键复用同一执行和取消凭据。
- 总结尝试在实际请求准入后计数；满收件箱分段接收和总结，未接收输入不确认、不丢失。
- 总结使用独立阶段缓存键；同一保留批次经历多次压缩不会复用前一份回复。
- 工具拒绝及反馈轮保留同一工作预算；循环中断显式继续归档旧失败回复，再做有限纠正。
- 最终选定的持久请求重新校验当前输出与总容量，暂停后缩减设置真正生效。
- 真实副作用执行结束前保持工作区写锁；未知结果阻断冲突写入。
  恢复前先全局隔离旧副作用，不因逐 Agent 恢复而抢先启动。
- 对账终态和待投递标记同事务保存，按可靠调度事件补投；满收件箱不阻断初始化。
- MCP 显式业务错误不再报告成功，断连后新操作重新连接；未知副作用不自动重发。
- Docker 采用受控 create/start，等待并检查删除结果，清理超时或失败保留未确认状态。
- 辅助记忆格式失败保留原文并继续正常工作；点名截止不被低优先级消息延后，
  按消息ID读取也遵守序号上界。
- 修复搜索结果到原文请求的字段映射，未读位置每会话只查询一次；
  移除 UI 组件循环引用、临时网络调试探针及示例对 Runtime 内部类型的依赖。

跨模块内部 schema 依赖已消除。通用 JSON 校验下推共享类型层，宿主输入使用 Runtime
公开校验契约；核心没有 Electron/React 反向依赖，新旧桌面没有互相导入。
`npm run check:architecture` 检查依赖方向与公共入口，已接入 CI。
架构细节见[模块化审查](architecture-3.0.0.md)。
