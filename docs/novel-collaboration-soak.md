# 前十章协作运行测试

此入口验证真实模型能否通过工具和消息完成持续协作，不评价小说情节、人物或文风。
它只在手动启动时调用付费接口，普通 `npm test` 不会触发。

```bash
DEEPSEEK_KEY_FILE=/安全位置/deepseek.key \
DEEPSEEK_MODEL=deepseek-flash \
NOVEL_SOURCE_DIR=/可选的小说资料目录 \
npm run test:novel:soak -- .tmp/novel-soak-run
```

也可通过 `DEEPSEEK_API_KEY` 提供凭据。Key 文件应限制为当前用户可读，不能提交仓库。
`NOVEL_SOURCE_DIR` 可省略；提供时只复制 `故事大纲_校对稿.md` 和 `大纲审读与待确认.md`，
测试 Agent 在独立工作区工作，不改动原资料。

宿主创建长期作者小白、只读编辑小黑及点名唤醒的协作群，只派发一次任务。
小白逐章写入、读回并交稿，小黑实际读取后要求一次简单补写，小白修改并读回，
小黑复读确认后再推进下一章。每章补写只用于覆盖修改和多轮交接，不是文学质量门槛。
允许模型自行使用上下文计划和压缩，权限与调度走正式 Runtime。

每3秒保存 `status.json`、`messages.json` 和 `events.json`；`runtime.sqlite` 保留请求、
回复、工具与调度证据，`workspace/交付/` 保存模型写出的章节。
检测到暂停、Runtime 故障、持续空闲或总时限时停止并保留现场，不自动注入催促消息，
不代写文件、不伪造编辑确认、不自动推定未知写操作成功。

默认单个工作批次128次请求，每位 Agent 全程30M Token，每分钟30次请求，
总时限2小时；`NOVEL_SOAK_TIMEOUT_MS` 可以修改总时限。
测试过程不自动重置额度。指定同一目录会恢复原数据库，暂停现场需由可信宿主处理；
验证一次运行的完整交付应使用新的空目录。

完成标志要求十个章节文件各有实际正文和补写小节、作者发出交付消息且两名 Agent 休眠。
最终验收还应核对数据库中的作者写入、编辑读取、消息交接和中断记录，不能只信完成文案。

运行结束后，使用只读核验脚本生成报告：

```bash
npx tsx examples/novel-soak-report.ts .tmp/novel-soak-run
```

脚本逐章检查双方在修改前读过初稿、作者至少两次实际写入、双方读过最终文件的 SHA256、
编辑在最终复读后确认，并验证作者实际写出列全十章的交付清单。
同时要求只有一条初始用户消息、至少60次模型请求、编辑没有写操作、最终均休眠且没有
需要人工处置的中断；自动重试保留在报告中，不按人工介入计算。
结果写入运行目录的 `verification.json` 和 `验证报告.md`，不完整或中断现场返回失败退出码。

2026-10-23 的第二轮现场位于 `.tmp/novel-soak-deepseek-02`：从空库一次派发，
176次真实请求、37条 Agent 消息、723秒后交付十章及清单，最终均休眠。
十章最终读取哈希及编辑确认均已核对，本轮没有HTTP400或402。
第08、10章提前将补写放入初稿，编辑直接确认，逐章独立修改流程覆盖8/10；
严格脚本保留 `passed:false`。用户运行目标与额外测试覆盖的区别记录在
该目录的 `运行目标验收.md`，不能据交付完成声称严格脚本全部通过。
