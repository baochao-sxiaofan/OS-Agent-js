# 请求布局与缓存复用

普通工作轮使用固定的控制工具定义；业务工具按 Agent 创建时的可见集合及工具名称排序。
工具名称、说明、参数 schema 不随任务阶段、来源编号或本轮调用而改变。
不同角色可见的业务工具可以不同。总结和会话记忆压缩各自使用固定的专用请求模板。
工具可见不等于授权；允许动作、角色规划策略、来源、能力和资源范围仍由宿主执行前校验。

## 消息排列

1. 固定系统规则、长期指令、角色定义。
2. `runtime_context`：身份与权限配置，然后按 L1、L2、L3 排列目标、计划定义和已归纳记忆。
3. `runtime_update`：当轮状态、来源、收件批次、近期工作记录和跨会话参考记忆。
4. 之后保留上一轮完整请求，追加真实 assistant 工具调用、配对的 tool 回执，再追加本轮增量。

增量以 path 指定对象字段或数组下标；value 替换、append 追加、remove 删除。
未提及字段保持原值。近期记录通常只追加新条目，不重复发送全文；旧调用 ID、参数、
回执和私有续接均不改写。私有续接只在原生历史中，不进入 Context 或会话记忆。
发生可纠正错误时，在增量之后追加简短明文反馈，避免实际纠正步骤埋在长状态中；
后续更新清空 `previousError` 后旧反馈失效，不修改工具定义或提前插入稳定前缀。
`readRuntimeRequest(request)` 为确定性 requester 和诊断工具还原最新语义视图，不能再假定
`messages[1]` 包含最新现场。业务控制仍读取 Context 当前事实，不从历史反向更新任务。

## 重建边界与恢复

同一 Agent、会话、工作批次和活动上下文作用域内，已有完整消息保持前缀不变。
计划定义、层级、总结、角色规则或工具配置改变时重建前缀；超出完整请求容量时从当前
语义现场重新构造，不逐轮删除最早的历史消息。原始持久记录保留。
不完整的工具调用组不重放，不伪造结果；实际副作用仍以原幂等键恢复。
请求协议版本为4：未完成旧格式请求归档后重建，已完成回复继续按原回执幂等提交。

DeepSeek 返回的 cacheHitTokens/cacheMissTokens 保存在 completion 及 model_completed 事件，
字段缺失与明确为0不同。输入命中率按总命中输入 Token / 总输入 Token 计算。
离线测试验证前缀、工具定义、恢复和权限不变量；真实平台命中率仍需实际 API 用量验证。

## 手动真实模型验证

`npm run test:novel:live -- <小说工作区> <独立运行目录>` 创建作者和只读编辑；
恢复时指定原运行目录，沿用同一数据库与两个身份。设置 `NOVEL_PROVIDER=deepseek`、
`NOVEL_KEY_FILE=<工作区外的密钥文件>` 和 `DEEPSEEK_MODEL`，不把密钥写进命令参数或仓库。
`NOVEL_REQUESTS_PER_MINUTE` 默认30，仍受 Runtime 准入与总额度约束。

`status.json` 的缓存统计来自已持久化的 `model_completed` 事件，包含模型正常返回后被
宿主拒绝的动作，不包含未能解析的供应商响应、取消请求或独立诊断调用；与平台时段汇总
口径可能不同。缓存命中率高不代表任务推进高效，应同时核对重复审稿、重试和实际产物。
该入口使用 `allowPlanning:false`，覆盖普通工具轮、会话记忆和恢复，不能据此声称已完成
L2/L3 活动计划的真实模型验证。该入口不会自动停止；本次实验以两名 Agent 协作生成十章文件为验收标准，
不以内容质量或宿主终审为门槛。操作者只检查文件交付、权限、请求与运行错误，随后关闭运行，
不在协作过程中追加创作或审稿指令。实测范围和干预限制见
[实测记录](./deepseek-novel-validation-2026-10-26.md)。
