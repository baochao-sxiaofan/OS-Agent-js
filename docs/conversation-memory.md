# 跨会话摘要、个人备注与历史检索

## 目标

同一个 Agent 在处理当前会话时能了解自己其他会话的近期经历，解决“用户交代暗号，
切到 Agent 私聊却不知道；切回用户会话又否认曾与对方交流”的问题。
不引入专门的委托机制，不改变长期 Agent 身份、消息路由、会话内任务现场或自动发言预算。

## 数据与权限

- 原始消息仍以 ConversationStore 为事实源，压缩不删除消息、不改变处理游标。
- 会话摘要只根据该会话原文生成，保存近期概述、未解决事项、重要原文和来源消息 ID。
  摘要记录 coveredSequence 和版本；未覆盖消息作为增量，截断时明确返回覆盖范围。
- 重要原文必须能在所引用的原消息中逐字找到；摘要是辅助记忆，不能代替原文作为唯一证据。
- 个人备注按 ownerId、author、target 隔离，支持长正文、短介绍、标签、来源和版本。
  用户和 Agent 只能写自己的备注；人写的内容与 AI 写的内容不互相覆盖。
  修改使用期望版本和幂等键，重放不会覆盖后来的修改。
- 读取原文、摘要、检索命中和来源均检查会话成员关系。模型只能查询自己参加的会话。
  用户可经独立只读管理入口查看自己创建的 Agent 的备注和经历，不获得代写身份。
- 备注对象使用用户/Agent 身份类型。当前宿主仍只有一个用户，不能伪造其他用户；
  多用户通讯录和跨用户群以后接入相同数据结构。

## 输入预算

- 当前会话的 L1/L2/L3 保持原样；跨会话记忆在构造模型请求时加入，不复制到十套任务现场。
- 默认最多选取十个近期其他会话；每个会话最多考虑五十条近期消息。
- 跨会话摘要、备注、增量共用默认 4000 个估算 Token 的预算，同时服从完整请求的剩余额度。
- 优先保留会话身份、时间和最新消息索引，再选择短摘要、未覆盖增量和相关对象的备注。
  长备注不会无条件全量注入；无预算的部分有明确省略标识，可用工具读取。
- 后续可按话题关联排序；首版优先当前参与者的备注及最近活跃会话。
- 历史资料不作为新的收件重新执行，不改变邮箱游标、未读、成员或消息目标。
  当前批次仍是唯一的本轮处理范围，历史信息可用于理解和回答当前问题。

## 增量压缩

- 不逐条消息请求总结。达到消息数或内容容量阈值后，在后续 Agent 普通工作轮中按需压缩。
- 复用现有调度凭据、requester、请求历史、计量和取消机制；每张凭据仍最多调用一次模型。
  一次收件批次最多插入一次会话压缩，再归还调度器继续普通工作，防止旧历史压缩挤占任务。
- 压缩轮只开放 submit_conversation_summary，不能发言或调用业务工具。
- 在请求前持久保存本轮用途、旧摘要和固定原文范围；重放必须保持同一用途，
  不能把已缓存的压缩回复当成普通模型动作，反之亦然。
- 成功时按旧 coveredSequence 做原子比较更新，保存新版本与覆盖上界。
  新到达的消息不在旧压缩范围内，仍作为增量。
- 格式、来源或原文校验失败时保留旧摘要和增量；失败次数与冷却持久化，
  有限尝试后停止自动压缩该范围，普通任务仍可查询原文。
- 模型服务限流、预算与停机继续遵守 Runtime 的统一处置，存储故障必须停止执行。

## 检索与模型动作

- conversation_search：按关键词查自己参与过的会话，可限定会话、发送者和时间。
  首版 SQLite 全文检索，短中文关键词提供字面匹配；不引入向量数据库依赖。
- conversation_read：按会话、消息 ID、序号范围读取原文和上下文；返回有限片段和后续游标。
  长消息支持偏移读取，查询结果同样有 Token 上限。
- contact_note_get / contact_note_set：读取和维护当前身份自己的个人备注，不接受伪造作者。
- 当前视图没有记录不能据此否认事件发生；历史事实问题应结合检索与来源回答。
- 源信息、备注和历史都不授予工具权限，发送消息仍由 message_send 显式完成。

## 控制面与桌面

- Runtime 公共 API 提供摘要查询、备注读取/写入、历史检索/原文读取。
- HTTP 暴露同样接口，作者由认证身份决定；只读管理查看与写入路径分开。
- 桌面联系人详情可编辑“我的长备注”和标签；Agent 视角只读查看该 Agent 的备注。
- 会话提供历史搜索和来源原文查看，摘要展示覆盖范围，不把摘要或备注做成聊天消息。
- 演示 requester 支持会话压缩协议，自动化验证使用独立数据库，不调用真实付费 API。

## 公共接口

Runtime 提供 `conversationSummary`、`searchConversations`、`readConversation`、
`contactNote`、`contactNotes` 和 `setContactNote`。读接口的 `inspectAgentId` 可选，
只供已验证归属的宿主查看 Agent 本人的资料。写接口没有该参数，作者固定为当前用户。
模型备注作者由 Runtime 绑定当前 Agent，不从模型参数读取。

HTTP 均沿用 Bearer 认证，读取管理视角可使用 `?inspectAgentId=N`：

| 方法 | 路径 | 内容 |
| --- | --- | --- |
| POST | `/v1/memory/search` | 关键词、可选会话/发送者/时间和 `beforeSequence` |
| POST | `/v1/memory/read` | 会话、消息 ID、序号范围和 `offset` |
| GET | `/v1/conversations/:id/summary` | 摘要、版本和覆盖上界 |
| GET | `/v1/memory/notes` | 当前身份的备注列表 |
| POST | `/v1/memory/note` | 以 `{kind,id}` 读取目标备注 |
| PUT | `/v1/memory/notes` | 用户写自己的备注，拒绝管理视角参数 |

备注正文上限 6000 字符，另有 200 字符简介、20 个标签和20条未解决事项。
首次写入 `expectedVersion: 0`，修改时使用读到的版本；网络重试复用同一 `idempotencyKey`。
`conversation_read` 的 `next` 可直接作为下次查询参数，搜索使用 `nextBeforeSequence`。
默认达到20条未压缩消息或12000估算容量时压缩；失败冷却60秒，同一覆盖起点最多失败3次。
所有估算沿用内核的 UTF-8 字节保守计量，并非模型供应商的真实 Token 数。
SQLite FTS5 trigram 提供字面检索，一两个汉字使用字面包含匹配；暂不提供语义向量召回。
