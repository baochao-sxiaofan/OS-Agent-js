# DeepSeek 小说协作实测（2026-10-26）

本记录描述请求布局重构后的真实协作测试。使用用户授权的 DeepSeek 账号，
从原始小说大纲派发作者小白与只读编辑小黑完成前十章、约三万汉字。
两名员工使用用户原始角色提示词；稿件由作者工具实际写入，审稿来自编辑真实消息。
私人原纲、生成稿件、请求数据库和凭据不纳入仓库。

## 配置与证据范围

- 模型为账号官方模型列表返回的 `deepseek-flash`，开启 thinking/high。
- 同一运行目录、数据库和两个长期身份贯穿运行及修复后的恢复，没有重建员工替换现场。
- 作者可读工作区，仅可写本次输出子目录；编辑仅有读取、列目录和搜索权限。
- 普通工作使用 `allowPlanning:false`，覆盖普通轮、记忆压缩、原生历史与恢复。
  本次不能证明 L2/L3 活动计划的真实模型表现；对应布局由离线测试覆盖。
- 工具目录按角色分别审计；“定义固定”不要求给只读角色暴露写工具。
- 缓存统计读取已持久化 `model_completed` 事件，包括模型正常返回但动作被宿主拒绝的情况。
  不包含解析失败的供应商响应、取消请求、模型列表查询和独立诊断重放。
  命中率为命中输入 Token / 有缓存测量的输入 Token，不能当作所有请求成功率。
- 没有同条件的修改前对照实验，因此不把命中率变化完全归因于某一处修改。

## 实际发现与修复

| 问题 | 证据与处理 |
| --- | --- |
| 工作区根 URI 有无尾斜杠不一致 | 解析器接受两种拼法，但权限与工具参数校验拒绝其中一种。统一规范化与校验，保留子树和不同挂载隔离。 |
| 模型返回不存在的工具名 | 正常 HTTP 响应把业务工具哈希后缀拼到 `message_send`。适配器拒绝执行；补充精确工具名纠正提示，保留有界重试。 |
| 审稿时反复要求读未变化的参考文件 | 参考稿内容哈希相同的完整读取可复用；正文修改后仍须读当前版本，终审要求十章最新全文证据。 |
| 错误纠正信息被忽略 | 状态增量中的错误仍被模型忽略，重复发送被拒绝动作。将简短明文反馈追加在请求最后，不改变工具或稳定前缀。 |
| 成功重试残留旧错误 | 动作复用原幂等键，已有动作标记跳过了错误清理。纠正动作成功推进时清除当前错误，保留历史中断。 |
| 中文长结果超过单次投递上限 | 内联按字符数判断，Context 按序列化 UTF-8 字节数限额。按包含外壳的实际字节数检查，超限转预览与分页；保留完整原文。 |

其他观察：模型多次漏填群聊 `mentions`、用旧文本打补丁、误用原文引用，
以及摘要引用无效。运行时拒绝无效操作，提供错误并有限重试，不伪造发送、
补齐目标或推定未知写入成功。运行中出现的请求准入等待是本地限速，
应与供应商 HTTP 错误分开统计。

运行期间宿主曾多次追加内容审校指令，超出了本次技术实验的必要范围，增加了修订和模型调用。
用户随后明确：实验以两名 Agent 协作生成十章为交付目标，宿主不应阅读剧情或干预内容。
收到纠正后停止内容检查和任务追加，按文件交付标准结束实验。
因此本次只能作为真实请求、权限、工具执行与恢复的观测记录，不能作为完全自主协作的证据。
