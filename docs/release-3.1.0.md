# OS-Agent-js 3.1.0

发布日期：2026-10-26。根包和 OS Agent Next 桌面版本统一为3.1.0，旧桌面继续保留2.2.1。

本次针对长任务中请求前部频繁变化、难以复用供应商前缀缓存的问题，重构请求布局，
并新增员工解雇功能。桌面与 HTTP 服务共用这些 Runtime 改动。

## 请求体重构与缓存复用

过去，普通轮工具 schema 会随当前允许动作、来源编号等现场变化，工具历史也可能在有限窗口中
滚动丢弃最早部分。即使大段内容重复，早期差异仍会截断可复用的公共前缀。
现在同一配置下普通轮控制工具定义固定，业务工具按角色可见集合稳定排序；
实际动作、权限、资源与来源仍在执行时校验，不通过扩大权限换取命中。

请求按变化频率排列：

1. 固定系统规则、长期指令和角色定义。
2. 身份与权限配置，随后按 L1、L2、L3 排列目标、计划定义和归纳记忆。
3. 当前状态、来源、收件批次与近期工作记录。
4. 后续轮保留上一请求的完整消息，追加真实工具调用、配对回执和当前状态增量。

错误纠正反馈放在末尾。上下文作用域、计划定义、总结、角色或工具配置改变，
以及完整请求达到容量边界时，才重建前缀。会话、权限与恢复边界始终保留。
不同角色可以拥有不同工具集合；普通轮、独立总结、会话压缩各有固定模板，
不要求所有类型请求使用同一套工具。格式细节见[请求布局](request-layout.md)。

DeepSeek 返回的缓存命中和未命中 Token 现在随 completion 与 `model_completed` 事件保存，
缺失值不会被当作0。缓存由供应商按请求前缀复用，桌面无需手动开启。

### 真实实验结果

使用 DeepSeek `deepseek-flash`，作者与只读编辑协作生成10章文件。
657次已持久化正常返回共17,455,361输入 Token，其中13,947,904命中缓存，
输入命中率为 **79.91%**；两名员工各自的普通轮工具目录全程各一套。
编辑业务操作只涉及读文件、列目录和搜索。

这不是对所有平台请求的完整计费统计：解析失败、取消请求和独立诊断重放不在该口径内。
没有同条件的修改前对照；此前平台时段汇总为0，不能据此断言其唯一原因。
本轮有宿主内容干预，不能当作完全自主协作或执行效率的验证。实验未启用 L2/L3 活动规划，
这些布局路径由离线测试覆盖。具体证据与限制见[实测记录](deepseek-novel-validation-2026-10-26.md)。

## 解雇员工

在员工私聊或 Agent 视角点击右上角详情图标，在“Agent 详情”面板最下方点击“解雇”，
确认后停止请求与工具执行、撤销授权并释放名额。
已解雇身份不再出现在默认员工列表，不能通过“继续”恢复；可查看其历史归档。
私聊转为只读，群聊其他成员继续工作。工作区文件与未知副作用的对账记录保留。
HTTP 提供相同能力，详见[服务器接口](server-runtime.md)和[桌面说明](desktop-next.md#解雇员工)。

## 联调修复与升级兼容

- 工作区根 URI 带或不带尾斜杠使用同一权限和参数校验，保持子树隔离。
- 中文长工具结果按包含投递外壳的 UTF-8 字节数检查，超限转预览与分页，保留完整结果。
- 模型使用不存在的工具名、遗漏参数或提交无效动作时，收到明确纠正反馈并有界重试。
- 复用原幂等键的纠正动作成功后清除当前错误，历史中断记录仍可查询。
- 请求协议版本升至4。未完成的旧格式请求归档后重建，已完成回复按原回执幂等恢复；
  不删除原始请求、会话、Agent 身份或工作区文件。升级前先正常退出应用。

## 验证

全仓61个测试文件、432项测试通过，覆盖固定工具与前缀、原生回执配对、恢复、
解雇并发取消与未知副作用、根 URI 别名、中文长结果分页及错误纠正。
核心与新旧桌面类型检查、80个生产文件的模块边界检查、核心构建和 macOS arm64 打包通过。
本机已替换安装3.1.0，并保留旧应用备份及现有用户数据。已安装包在独立演示数据目录中，
以正常 Chromium 沙箱验证启动、聊天、界面解雇、历史保留、群聊其他员工继续回复及重启恢复；
已解雇身份重新启用被拒绝。该窗口验收没有调用付费模型。
macOS 本地应用包未签名或公证；Windows 安装器由远端 CI 构建，不以 macOS 验证代替 Windows 实机验收。
