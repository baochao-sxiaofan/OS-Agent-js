# 长期 Agent 桌面端

当前版本：3.1.0（2026-10-26）。本次请求体重构、缓存实测与解雇功能见[发布说明](release-3.1.0.md)。

目标：提供类似飞书/微信的联系人与对话界面，运行新 ACB → scheduler → round →
Context → requester 链路。所有 Agent 由用户创建，保持长期身份；后端组件仍可单独用于服务器。

## 接入边界

- `desktop/` 保留旧 TCB/Graph 桌面；`desktop-next/` 是独立 Electron workspace。
- 新桌面的主进程只通过新 Runtime 的公共入口管理 Agent，渲染进程通过窄 IPC 接口操作。
- 主进程管理模型凭据、用户选定的工作区、联系人显示信息；核心模块不依赖 Electron/React。
- 新桌面使用独立的数据目录，不读取或自动迁移旧桌面的任务库。
- L1/L2/L3 属于一个 Agent 的内部上下文；桌面不展示父子 Agent 或创建任务树。

## 界面与行为

- “我的对话”仅展示用户参加的私聊和群聊，支持搜索、最近消息及会话未读。
- “Agent 视角”展示长期联系人，可只读查看其私聊、群聊和旧版归档；查看不改变未读、
  不加入会话、不触发模型。通过“与它私聊”返回用户对话。
- 左上角“＋”打开创建面板：名称、长期职责、角色、可选工作区及读写权限。
- 创建后先休眠，用户发送消息才唤醒；完成后保留身份、记忆和对话，支持后续消息。
- 右侧展示所选会话消息，标明发送者、点名和回复引用；Enter 发送，Shift+Enter 换行。
  草稿与点名选择在窗口内按会话保存；关闭窗口不持久保存未发送草稿。
- 对话列表顶部可创建群，选择同工作区成员与“自主判断/仅点名”策略，输入框可选择 @ 对象。
- Agent 私聊与管理视角保留详情、暂停/继续、故障和审批操作。群详情可进入成员管理。
- 会话分别展示聚合等待、处理中、已处理；不会把其他会话的忙碌显示成当前会话正在回复。
- 模型设置支持 MiniMax 和 DeepSeek，分别保存凭据与上次选择的型号；
  凭据只在主进程使用，可用时通过系统安全存储加密。
- 本地演示使用显式消息和静默结束，普通业务的独立总结仍保留。演示群聊仅对被点名
  消息回复；真实模型按职责、指向和已有回答判断。通知或不需要补充的答复可静默处理。

## 跨会话记忆的使用

- 会话右上角“会话记忆”展示自动摘要、覆盖序号和未纳入摘要的消息数量；
  点击“来源”可核对原文，长消息用“继续阅读”逐段打开，也可以查看前后消息。
- 右上角搜索按钮打开“历史搜索”，可选择当前会话或全部可访问会话，输入原文关键词；
  “加载更早结果”继续翻页。首版提供 SQLite 字面检索，暂不提供语义向量搜索。
- 在联系人详情点击“编辑我的长备注”，填写简介、正文（最多6000字符）、标签和
  每行一项的待跟进，可选关联本会话最近消息作为来源，再点击“保存备注”。
  保存时检查版本；发生冲突会保留当前表单，需先保留草稿再重新读取。
  未保存表单仅留在当前编辑页，切换对象、切换分类或关闭弹窗会丢弃。
- “Agent 视角”中的详情提供“查看 Agent 的备注”，可选择用户或其他 Agent 作为
  备注对象。这里展示该 Agent 写的内容，只读且不会显示用户自己的备注。
- 备注与摘要不会产生聊天气泡。历史查询和来源阅读不清未读、不改变会话成员或处理游标；
  人类与 Agent 各自维护自己的备注。当前宿主只有一个用户，多用户通讯录尚未接入。

同一个 Agent 的近期其他会话摘要、增量和相关对象备注共用容量预算，需要更多内容时
由模型调用检索与原文工具。会话压缩在达到阈值后的普通工作批次内按需进行，打开
记忆面板不会触发模型调用。预算和完整协议见[跨会话记忆说明](conversation-memory.md)。

## 运行

### 在 Mac 上直接使用

安装后双击「应用程序」中的 `OS Agent Next.app`，也可以通过桌面快捷入口打开，
无需启动终端或单独运行服务器。首次启动默认进入本地演示模式。

1. 点击左上角「＋」，填写名称和长期职责，选择角色；需要文件操作时选择工作区，
   并授予「只读」或「读取与编辑（不含删除）」权限。
2. 创建后在「我的对话」中选中 Agent，发送第一条消息开始工作。
3. 本地演示只用于体验界面和固定回复，不调用真实模型、不操作工作区文件。
4. 需要实际写作、阅读和编辑时，打开左下角「模型设置」，选择 DeepSeek 或 MiniMax，
   输入对应 API Key，再从「具体型号」下拉列表选择，点击「保存设置」。
   DeepSeek 在输入停止后自动从官方接口读取型号，可用「刷新列表」重试；
   MiniMax 展示官方预置型号，实际可用性取决于账户和套餐，不代表已验证 Key。
   切换前等待工作结束或暂停 Agent。两家连接各自记住已保存的型号和凭据。
5. 多 Agent 协作时，为它们选择同一个工作区，再点击「创建群聊」选择成员。
   群聊采用「仅点名」时，在输入框明确选择要唤醒的 Agent。

作者需要编辑权限，可选择「开发工程师」并在长期职责中填写写作角色；
只读编辑可选择「代码审计员」并填写审稿职责。角色控制工具范围，长期职责描述具体工作。
小说手动联调保存在独立数据库中，不会自动出现在新安装应用的联系人列表。

### 从源码构建

```bash
npm install
npm run desktop:next:dev
npm run desktop:next:check
npm run desktop:next:build
npm run desktop:next:pack
```

Windows 安装器使用 `npm run desktop:next:dist:win`，输出
`OS-Agent-Next-Setup-3.1.0-x64.exe`；远端 Windows CI 会构建此产物，本地 macOS
验证不等于 Windows 安装器已实机验收。旧桌面继续保留2.2.1版本。

打包输出在 `desktop-next/release/`，macOS Apple Silicon 为
`mac-arm64/OS Agent Next.app`。本地包未签名或公证；当前验证平台为 macOS arm64。
将该 `.app` 拷贝到「应用程序」即可安装，更新前先退出旧实例；数据保存在下述独立目录。
预加载脚本固定打包为 `out/preload/index.cjs`，兼容正常启用的 Chromium 沙箱，
主进程继续使用 ESM。无需开启预览开关即可正常加载 IPC 和界面。
旧桌面仍由 `npm run desktop:dev` 启动。

默认数据目录为 `app.getPath('appData')/OS Agent Next`；macOS 对应
`~/Library/Application Support/OS Agent Next`。可通过 `OS_AGENT_NEXT_DATA_DIR`
指定独立目录。`desktop.sqlite` 保存联系人名称、已读位置、工作区映射和加密模型配置；
`runtime.sqlite` 保存新链路的身份、对话、上下文、调度、审批与执行记录。
恢复前应保证已登记的工作区路径仍存在，不允许同一工作区标识改指其他目录。

桌面权限校验使用主进程维护的工作区登记表；渲染进程不能自行提交路径作为授权。
用户可授予只读或读取/创建/编辑权限，不含删除、任意 shell 或权限转授。
审批结果未知时先核对实际副作用，再从界面提交结果和继续执行。

`MINIMAX_API_KEY`、`DEEPSEEK_API_KEY` 仅作为各自供应商的本地主进程凭据来源，
不自动打开真实模型模式，不跨供应商借用。
凭据不进入 Runtime 数据库、渲染快照或模型上下文。模式/模型切换要求所有 Agent
休眠或已暂停；保存配置不触发付费请求，后续发送消息或继续任务时使用新连接。
DeepSeek 型号发现只请求官方 `https://api.deepseek.com/models`，不会执行推理；
临时输入的 Key 仅用于本次读取，点击保存后才成为当前配置。
DeepSeek 普通工作默认开启思考；必须调用指定函数的总结与固定控制步骤使用
非思考模式的原生强制工具参数。工具协议和私有续接状态由适配层处理，不展示为聊天内容。
普通动作、分层总结和会话摘要统一通过原生工具调用提交，提示词与网络请求使用同一契约。
近期工具调用只在同一工作和上下文范围内续接，保留实际调用 ID、真实结果和思考状态；
只有已完成且上下文已提交的完整调用组进入后续请求，私有状态不进入记忆或聊天。
列表为空、网络失败或 Key 无效时显示原因并允许重试；已保存但不在列表中的型号
仍可辨认和保留。旧 MiniMax 单连接配置自动按新结构读取，联系人与历史不迁移、不清空。

模型设置中的“上下文与输出容量”提供500K、1M预设及自定义整数。默认单次请求容量
500K、单次最大输出32768；每层硬上限140K、自动压缩阈值100K、压缩后目标50K。
预设同时调整每分钟和累计额度，避免更大的请求被旧配额阻断。也可单独填写输出上限，
例如65536；实际支持的窗口和输出容量取决于所选模型。完整请求仍执行总容量预检。

保存要求 Agent 已休眠或暂停且本轮请求已退出；设置会持久保存并应用到已有 Agent 的
所有会话上下文及后续请求。已有现场超过新硬上限时拒绝降低容量，保留当前设置。
升级代码后需重新打开桌面一次，之后调整容量无需重启。失败总结暂停后可先提高容量，
保存设置，再对该 Agent 点击“继续”：旧失败回复归档，原任务从总结阶段重新尝试，
不重发用户消息、不重做已提交业务。原始历史和工具权限保留，累计计量不会清零。
JSON 语法问题仍须通过结构与来源校验，提高容量不保证模型每次都能提交合法总结。

默认128次模型请求上限作用于一个工作批次；新的收件批次取得独立额度，
同一批次的自动重试和应用重启不会清零。额度耗尽后暂停，点击“继续”可追加一份额度。
联系人详情中的累计请求数、Tokens 和费用继续保留，累计 Token 与费用限制仍然生效。
升级前已因终身128次上限暂停的 Agent，重启新版后点击“继续”即可申请当前工作的额度。

L1/L2/L3 的来源按当前活动步骤提供和校验。已完成任务的长结果在压缩后保留短预览和
封存引用，原文仍可读取；总结可用容量扣除固定结构及来源还原开销，减少提交后超限。
协议错误会携带脱敏纠正提示有限重试；已保存的旧版回复只在恢复路径兼容读取，
新的模型回复须使用原生工具调用。

受限环境的本地预览可显式使用：

```bash
OS_AGENT_NEXT_PREVIEW=1 OS_AGENT_NEXT_DATA_DIR="$PWD/.desktop-next-runtime" npm run desktop:next:dev
```

该预览开关仅为兼容当前机器的 Chromium 启动限制，关闭 Chromium 沙箱与硬件加速。
正常启动不启用它；Context isolation、关闭 Node integration 和工作区能力校验仍保留。

- 当前模型接口为非流式请求；聊天显示完整回复。附件、多用户成员管理、群成员动态变更
  和远程同步不在本次范围。
- 请求次数按工作批次限制，Tokens 和费用上限仍由核心累计计量，达限后暂停；
  UI 的 Tokens 为预算计量，供应商未报告用量时包含保守估算，演示不产生真实费用。

## 解雇员工

在员工私聊或 Agent 视角顶部点击“解雇”，确认后停止该员工的模型请求和工具操作，
撤销可执行授权并释放员工名额。解雇身份不能通过“继续”重新启用；如需重新聘用，创建新 Agent。
默认员工列表隐藏已解雇身份，可用“查看已解雇员工”查阅其历史及待对账操作。
私聊保留历史且不能发送新消息；群聊保留过去发言，其他在职成员继续工作，不能再点名离职员工。
已有工作区文件不删除，结果未知的写操作仍须对账，解雇不会把未知结果当作失败重做。
