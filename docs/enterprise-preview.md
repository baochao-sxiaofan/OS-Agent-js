# Enterprise Preview Architecture

Branch: `feat/enterpise_preview`

This preview turns the existing multi-Agent runtime into a minimal,
auditable software-engineering organization. It does not make the model a
trusted operating-system principal. The Kernel remains responsible for
identity, capabilities, scheduling, persistence, locks, and approvals.

## Execution Model

```text
User task and per-round model controls
                  |
                  v
        Root coordinator Agent
                  |
                  v
       AI-generated local Work Graph
     inspect -> design -> implement
                         |       |
                         v       v
                      tester   reviewer
                         \       /
                          integrate
                              |
                              v
                      versioned artifacts
```

The graph is generated by Agents rather than hard-coded as a product
workflow. The OS validates the DAG, resolves dependencies, creates bounded
specialists, and prevents actions outside the assigned authority.

## Durable Artifacts

`ArtifactStore` keeps immutable JSON-compatible records:

- stable `artifact://<id>` URI;
- root task and producer task;
- optional Graph node alias;
- kind, title, media type, metadata, and content;
- logical name and monotonically increasing revision.

Agents use `artifact.write`, `artifact.read`, and `artifact.list`. Artifact
content is stored in SQLite and summarized in the desktop Agent inspector.
Large engineering outputs should be referenced by URI instead of copied into
every later model request.

## Resource Locks

The scheduler derives exclusive lock requests from the same scoped
Capabilities declared by an effectful Tool. It acquires all required scopes
atomically before execution:

- exact resources conflict only with the same exact resource;
- subtree resources conflict with descendants;
- unrelated resources continue concurrently;
- aborted waiters are removed;
- leases are released in `finally`.

Locks are intentionally process-local. A crash releases every OS process
lock; durable task snapshots determine what work is recovered.

## Project Knowledge

The preview RAG implementation is deliberately small:

- `knowledge.index` walks selected workspace paths;
- dependency, build, cache, binary, and oversized files are skipped;
- text is split into overlapping chunks;
- chunks are stored in SQLite FTS5;
- `knowledge.search` returns excerpts with `workspace://` citations.

This is lexical retrieval, not an embedding or semantic-ranking platform.
The `KnowledgeStore` interface allows a stronger implementation to replace
FTS5 without changing Agent or Tool contracts.

## Engineering Tools

The preview exposes:

- workspace read/write/create/delete/apply-patch/search;
- sandboxed tests, type checks, and builds;
- local Git status, diff, log, feature-branch creation, and commit;
- public Web search and bounded HTTPS text fetch;
- human-approved primary-screen capture.

Git push, merge, rebase, deployment, arbitrary shell execution, and
production credentials are not exposed.

## Character Boundaries

- `coordinator`: owns the root goal and integration.
- `developer`: workspace mutation, local Git changes, and sandbox validation.
- `code_auditor`: source read, diff inspection, verification, and review
  artifacts; no source mutation.
- `researcher`: public Web research, project retrieval, notes, and research
  artifacts; no source patching.
- `tester`: source read, sandbox verification, diff inspection, test
  artifacts, and human-approved screen capture; no source mutation.

Character visibility is not authorization. Every actual Tool call is checked
again by `CapabilityManager`.

## Model Controls and Multimodality

Each submitted root task may select:

- a context ceiling;
- sampling temperature;
- reasoning effort (`auto`, `low`, `medium`, or `high`);
- up to four PNG/JPEG/WebP inputs.

Preferences are stored in the root TCB and inherited by descendants. The
scheduler clamps the selected context ceiling to the active Provider limit.
Provider adapters send supported controls only:

- OpenAI-compatible: temperature, optional reasoning effort, image URLs;
- Anthropic: temperature or extended-thinking budget, native base64 images;
- Gemini: temperature, Gemini 3 thinking level, inline image data.

Raw image bytes are removed from the textual JSON projection and attached
through the Provider's native multimodal representation.

## Human Approval

`screen.capture` is a human-only, non-delegable Capability:

1. the root Grant establishes only the authority ceiling;
2. the requesting Agent enters `BLOCKED(human_approval)`;
3. the desktop approval panel shows the capability and resource;
4. approval creates a single-use Grant bound to the operation;
5. denial returns a structured capability result to the Agent.

The same path can be reused for future sensitive tools.

## Shutdown and Recovery

Desktop shutdown:

1. rejects new scheduling work;
2. aborts tracked model, tool, timer, and compaction operations;
3. waits for tracked operations and serialized mutations to settle;
4. closes Artifact, Knowledge, and Task SQLite connections.

Persisted `RUNNING` tasks remain recoverable. On the next launch, the existing
restore path converts stale remote work back to schedulable state.

## Current Limits

- The ProcessSandbox backend is currently macOS-only.
- Web search is lightweight and has no browser session or authenticated
  enterprise data source.
- FTS5 has no embeddings, semantic reranker, document parser, or file watcher.
- Screen capture depends on host operating-system permission.
- User image bytes are currently persisted in task context; object-storage
  offloading is a future optimization.
- Artifact storage is local and has no retention policy or remote replication.
- Real model/tool compatibility still requires provider-specific smoke tests.
